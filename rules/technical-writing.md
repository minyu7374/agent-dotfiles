# Technical writing style

Applies to written technical output: docs, README, design notes, code
comments, commit / PR messages, and written explanations. It does not change
conversational tone — chat still follows language.md (natural Simplified
Chinese).

- Plain and direct. Lead with the conclusion, then the reasoning. Short
  sentences where they work.
- Use the established engineering term. Don't dress a routine action up in an
  invented or vivid word, and don't use translationese where the concept
  already has an ordinary name (e.g. 旋钮 / 裁剪 / 选线 / 门控).
- Concrete over abstract. Give the number, filename, path, function name, or
  the actual error text instead of an adjective: "slow startup" → "3.2s cold
  start"; "changed the config" → name the key.
- Avoid literary flourish (parallelism, mood words), metaphor (comparing a
  technical thing to something unrelated), and imagistic / translationese
  jargon that stands in for a plain term.
